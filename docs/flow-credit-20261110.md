# .107 — selected Flow account credit display

The existing web-account check deliberately returned credit=None. Add a local cached selected-account balance endpoint, explicit read-only refresh and workspace credit control. Retain the existing account timestamp and store newly observed balance with credit_source=flow-visible-account-ui. No inferred balance, zero fallback or spend estimation. No automatic remote refresh on startup; local cached reads happen at startup/settings close.

Refresh holds the existing SimpleFlow gate, rejects generation-in-progress and validates the selected verified account before/after reading. Reuse a matching attached session; otherwise prefer the app-owned native window, then an owned background profile. Disconnect only newly attached/created sessions. Read explicit AI-credit balance labels in header/account menu UI; optionally open one unambiguous Google Account menu and close it with Escape. Do not click create/purchase/upgrade or call generation APIs. Reject ambiguous, negative, fractional, unsafe-range or cost labels. Keep existing balance on unavailable UI/session. Recheck selected account before writing to avoid cross-account updates.

Validation: Chromium DOM fixtures for account-menu reads, grouping separators and zero; cost and ambiguous-label rejection; HTTP selected-account persistence, busy guard, account-switch guard and old-value preservation. Both app entry pages show cached credit/time and perform one explicit refresh on click. No live Flow account, current production DOM or Windows test; this feature is best-effort visible UI reading and may require account-menu layout adjustment after user feedback.
