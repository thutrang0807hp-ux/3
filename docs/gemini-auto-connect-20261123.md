# SceneForge .162 — automatic Gemini connection, no code

The Gemini user flow is now install/reload extension -> open Chrome/Edge signed into Gemini and SceneForge -> account appears automatically. No issue/claim/code exchange or SDK cookie export is used for automatic Gemini connection. Existing frame/source/reference/prompt/approval/version logic and browser-generation transport from .161 remain unchanged. Code pairing is retained only for Flow/backward compatibility; Gemini account UI redirects to an informational automatic-status panel with no code controls.

Extension 1.7.1 probes default loopback port8840 on startup and while active, with Chrome alarms resuming discovery. An installation UUID reuses the same broker route/account. A local-only content script announces an actual SceneForge browser page's origin to learn custom ports. If no Gemini tab exists the extension opens one, retaining the pending tab to avoid repeatedly opening sign-in tabs. It then reuses the authenticated browser transport. App settings watch status and refresh the account list automatically. Additional Chrome profiles do not steal an already selected available automatic browser connection; an old manual-code/SDK connection does not prevent initial automatic selection.

The discover endpoint is inside the existing exact extension Origin/header/loopback boundary. It returns only a scoped broker capability; no Google credentials. Identity verification still requires the browser to expose a Gemini editor before a ready account is stored/selected. Existing manual routes do not count as proof the new automatic extension has connected. Repeated discovery is idempotent. Normal Gemini UI and popup no longer ask for a code; the collapsed code form is labeled Flow only. Account reconnect and Google configuration entry points use the same automatic path.

Validation: full production Gemini adapter, account pool, admission, SQLite ledger and broker were loaded with the actual frame node in Chromium. A simulated extension wire executed the actual injected DOM function: no-code discovery created/selected the browser account, the existing node sent two references once, a real PNG was committed and imported into the original scene, and no SDK was installed or auto approval performed. The Gemini website was a controlled DOM fixture. Actual automatic-worker source with Chrome API stubs verifies startup discovery, stable installation identity and no code/cookie payload. Actual shell UI verifies automatic account appearance without clicks and no pairing/SDK-login calls. Actual bridge tests verify Origin guard, discovery idempotence, legacy-to-auto selection, browser identity/account persistence and Flow protocol4 compatibility. Existing browser worker/transport regressions pass. Cumulative updater preserves .161 except reviewed auto-connection modules/UI/extension ZIP.

An attempt to install the actual extension in managed Chromium155 was blocked by administrator policy (Extensions.loadUnpacked). It was not bypassed or counted as a passing installed-extension test. Native Windows and a live Google account remain unverified. Custom-port desktop instances must be visited once in Chrome/Edge so the extension learns that port; default8840 needs no such step. Chrome suspension can defer probing until its 30-second alarm. Google UI/entitlement limitations remain those of .161.
