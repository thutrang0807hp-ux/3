# SceneForge .152

Resolves the .151 audit's recovery/state conflicts. Gemini worker now keeps a descriptor for the generated image and supports a strictly receive-only operation. It downloads full-size, then one standard rendition of the same generated image if necessary; records actual variant/dimensions and never reruns generation for a download failure. SDK HTTP status lost in a manually constructed HTTPError is extracted only from its known bounded message prefix. No raw exception text/URL is logged.

Per-request descriptors, original account and exact turn metadata are kept in the encrypted vault; plain ledger stores only availability/account and safe errors. Receive endpoint is task-deduplicated, restores the same request ID and file, and can recover .151 cursors only when request_id matches exactly. Worker history matching requires the original cid/rid/rcid and never substitutes the latest turn. A missing exact cursor/pointer returns a clear error instead of creating. Initial generation may make one bounded receive attempt automatically; explicit later clicks only receive that request. Concurrent done callbacks check task identity to avoid removing a replacement receive task.

Frame signatures v2 use persistent asset identities and anchor/reference identities instead of session blob URLs. Legacy unmatched signatures require explicit review before importing the exact request's image, without approval. Transient current errors are moved into history on completion. Both whole-node and per-scene explicit regeneration allocate new conversation scopes and preserve old receipts.

Validation: pinned real SDK types with fake HTTP 403/full-size failure and successful standard rendition, exact old-history matching and refusal of missing turns; actual adapter generation → failed transfer → adapter restart → receive same request/file (one generation), double-click deduplication, encrypted pointer vs plain ledger, .151 cursor migration; Chromium one-click create, bounded auto-receive, page reload with changed blob URL and stable signature, exact image import with zero additional generation and no auto approval; direct generation, inspector, per-scene/whole-node retry regressions; Python/inline-JS syntax; cumulative payload hashes/bytes. No live Google account/generation or Windows updater execution. Provider-side download success is not guaranteed.
