# SceneForge .153

Frame images now have one lifecycle owner. Scene/node actions and the legacy direct-image picker delegate to SFFrameImages; the existing automatic pipeline calls the same private processFrameImage operation. This is a facade over the existing running/preparing lock and durable promptPipeline/cloudJobs state, not another queue or storage schema. The common operation checks old receipts first, receives existing images without generating, prepares a local recipe only when needed, reuses a matching existing image unless regeneration was explicitly requested, and uses the same image sender/poll/importer. Importer calls are restricted to the selected scene. Repeated receive on an already imported image is idempotent. Explicit scene/node/picker actions may ask once to import an exact legacy request whose old signature cannot be compared; automatic frame runs do not silently accept legacy mismatches.

Removed frame preparation/submission branches from the legacy direct-provider sender; its remaining sender handles videos only. Compatibility prepareImage is local preparation, not an implicit writer. Optional image optimization in the old prompt tool delegates to the same node writer slot; readImagePrompt validates an existing writer receipt and cannot start a writer job. Legacy history decoders remain available for saved results. Existing automatic frame approval remains in the automatic caller, after the common creation/reception step; explicit scene creation does not auto approve.

Scope: sample-video/Motion workflow frame-image entry points. Separate Motion Studio reference-kit images, photo storyboard generation and video Flow/Muse remain separate product workflows sharing the existing backend adapter. No server/SDK changes in this release; builder verifies every previous .152 backend byte unchanged. No new model/runtime.

Validation: actual Chromium legacy caller and picker, node/scene generation, local compatibility preparation (zero writer calls), reuse of matching unapproved output, automatic frame review without regeneration, optional prompt UI sharing the node slot, pending prompt read without extra POST, two concurrent entry points (one image request), and legacy entry recovering an old image with zero image-generation POST/duplicate import. Existing real-source/product attachment/native fallback, original-image receive after reload, stop/restart and inspector regressions pass. Inline JavaScript and cumulative payload byte/hash checks pass. Tests use real images/SDK types with fake transport; no live Google account or Windows updater execution.
