# .105 — cookie/fingerprint-only profile retention

User explicitly requested cookie/fingerprint-only retention after reviewing the disk cost and session tradeoff. This supersedes the .104 conservative default. Idle maintenance runs 15 seconds after startup and then once per minute. It retains Local State (encrypted cookie keys), Cookies with SQLite sidecars in Default/Profile N, Preferences/Secure Preferences, Last Version and the existing SceneForge fingerprint/profile/browser/seed markers. Remaining ordinary files in recognized app-owned profiles, including site Local Storage/IndexedDB, cache, history and downloaded browser models, are eligible for removal. Empty directories may remain. The browser recreates working files during use; this does not impose a hard limit on open-browser disk or RAM usage.

The existing busy checks, shared launch gate, process inspection, singleton checks, bounded complete scans, metadata tokens and no-symlink/junction restrictions apply unchanged. The old cache-only endpoint remains for compatibility. Settings now uses explicit profile-lite endpoints and describes what is removed. Only browser-profile contents are affected; SceneForge project library, models and encrypted account vault remain outside this scope. Some providers may require login again when site storage is removed; fingerprint is not an authentication credential.

Validation: real Chromium restart reads the retained cookie after explicit lite cleanup; cookie database, Local State and fingerprint bytes are identical before/after cleanup. localStorage data and the test IndexedDB database are absent after restart. SceneForge project sentinel and external/unowned paths survive. Cache-only compatibility and actual Settings UI/API tests pass. No real provider login or Windows execution, so no universal session-retention guarantee or claimed MB target.
